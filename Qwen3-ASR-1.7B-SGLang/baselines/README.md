# 基线及比较范围

同框架对照使用SGLang的eager与decode graph，保持同Notebook、同音频、BF16、8192上下文、最大运行请求32、显存比例0.60、CPU4线程、greedy/1024自然EOS及缓存配置，仅切换执行模式。

- 并发1沿用原短测：每候选4条计数请求，另2条顺序预热；eager 8.0796、graph 30.9579音频秒/墙钟秒，提升283.16%。
- 并发4采用独立并发预热补测：每候选启动新服务，先3批并发4预热共12条，再计时3批共12条。按三批音频总秒数除以三批墙钟总秒数计算，eager 19.3768、graph 49.5455音频秒/墙钟秒，提升155.69%。两配置全部文本与原固定音频结果一致。
- 两配置最后两批预热及全部计时批次未发现服务时编译告警；复用已有磁盘编译缓存，不作为冷启动因果消融。graph三批计时吞吐为62.1902、62.9959、34.9691，全部计入合计，没有剔除较慢批次；未将无编译告警等同于完全没有编译或吞吐已稳定。

并发4证据见[补测汇总](../results/c4-warmup-20261103T114812Z/summary.json)、[独立统计及日志复核](../results/c4-warmup-20261103T114812Z/independent-check.json)和[原始记录目录](../results/c4-warmup-20261103T114812Z/)。复跑入口为`bash warmup_c4.sh`。当前报告使用上述并发4补测结果；较早短测原始记录保留供核查。

完整音频性能另有128计数请求、16预热，报告第二轮，不外推短测提升。原vLLM的test-clean WER1.6501%、音频吞吐32.20/53.63/61.56/68.86仅为跨框架历史参考。发布者test-clean WER1.63%，评价设置为BF16/greedy/1024/自动语种，完整归一化等价性未确认；不能据未知赛事容差声明官方通过。原vLLM预测及官方300输出均不复制为本框架结果。
