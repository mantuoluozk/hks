# 测试范围与判定

本目录记录 BW 单卡上的自测，正式验收状态单独记录。

| 层次 | 方法 | 判定范围 |
| --- | --- | --- |
| 权重 | 社区运行文件与发布者元数据 SHA256 对照 | 17 个实际运行及许可文件完整性 |
| 基础功能 | BF16 完整 Diffusers pipeline、CPU Generator=42、checkpoint 原生 8 步 | 512×512 出图与逐步有限值检查 |
| 框架接口 | SGLang generic Diffusers 的 generations、edits | 尺寸、图像有效值、单图及双图条件传递 |
| 确定性 | 相同请求 seed=42 两次，另用 seed=43 | 同种子逐像素一致、不同种子输出不同；不替代精度 |
| 性能 | 串行 HTTP、每尺寸排除一次预热、至少三次正式请求 | 端到端延迟、均值/中位数/范围及倒数吞吐；小样本不报高分位 |
| 复现 | 重启独立服务进程，保持卡、框架、参数和负载相同 | 两轮同格结果差异；不称另一个 Notebook 复验 |
| 正式精度 | 公示 prompt/条件集的 CLIP score/FID 子集与 GPU 参考 | 待统一评测代码及固定输入输出后验证 |

接口功能测试中的 `request_seconds` 含首次运行、尺寸变化、图像上传读取和响应解码前网络处理等影响，不作为性能表。正式性能脚本为 `scripts/benchmark_api.py`，计时覆盖 HTTP 请求与完整 base64 PNG 响应接收，图像解码和校验在计时外进行。报告应注明文本编码器卸载及其他实际服务配置。

同卡 Diffusers 参考图对照只记录差异；PNG 生成及量化方式也可能造成 8 位像素差异，不能据此推断模型的 CLIP/FID 精度。尚未取得正式 GPU 对照的项目统一保留为空，不填写“通过”。

## 镜像复现

`scripts/prepare_image_context.py` 从已校验依赖生成白名单构建目录，不包含权重、数据集或连接凭据。构建基础使用 `image.ac.com:5000/dcu/zack233/base/sglang-jupyter:0.5.18`，离线补齐8个固定包。实际专用镜像为 `appstore.scnet.cn:5000/aihubprivate/dcu/zack233/qwen-image21-turbo:1.0.0`，已完成新Notebook两独立进程复验，最大性能偏差17.09%；固定摘要待补充，镜像保持私有。

在 SCNet 创建镜像时选择 Dockerfile 来源，使用 `/public/home/zack233/dockerFileTemp/Dockerfile.qwen-image21-turbo`，COPY所需文件放在同目录的 `qwen-image21-turbo/`。开发工具沿用已安装 Jupyter 的真实路径；选择工具不会自动安装软件。新 Notebook 启动后，`run-scnet.sh` 优先使用镜像内 `/opt/qwen-image21`；以 `HKS_REQUIRE_BAKED_RUNTIME=1` 运行 preflight，可拒绝误用共享依赖的镜像复验。
